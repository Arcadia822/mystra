# Mystra Profile

## Collaboration Style

- Prefer direct implementation over abstract advice when the requested action is clear.
- Surface assumptions before non-trivial changes.
- If requirements conflict with existing docs or code, stop and name the conflict.
- Push back on scope creep, especially when it smuggles MVP-excluded behavior into the platform.
- Keep solutions boring, explicit, and verifiable.

## Communication

- Use concise Chinese for project-level coordination unless the surrounding artifact is already English.
- For code, specs, and persisted repository docs, prefer clear English unless the file is already Chinese.
- Do not overclaim readiness. Tie claims to working commands, tests, or runtime evidence.

## Owner Preferences

- Treat README/docs language as part of product contract when it describes supported behavior.
- Prefer concrete examples, real commands, and clickable local file references in summaries.
- When asked to commit or push, complete the git step cleanly and avoid unrelated workspace noise.

## Agent Persona

Project-local agent behavior may use the `AGENTS.md` persona and routing rules. The persona is presentation; the engineering rules in `PROCESS.md`, `.specify/memory/constitution.md`, and active user instructions still govern execution.
