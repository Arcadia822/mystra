要让 Mystra 执行什么？

把这一页收回到最小闭环：先选一个 project，再用自然语言交代目标、背景和验收条件。workflow、agent、repo、runtime 和 runner eligibility 都由服务端根据 project 默认配置推导，不在首屏要求用户判断。

创建 Mystra 任务

提交后会创建 `task`，解析 project 默认 workflow，并把你送到对应的 run detail。没有弹层。没有执行预检。只是一次干净的交付入口。

First-screen contract

为什么这里只剩两个动作

因为用户不是来配置 runner 的。任何需要 project 默认配置、workflow contract 或 runtime image 才能推导出来的内容，都不该在首屏向用户索取。

  • No projectcomposer 可写，但提交不可用。页面明确提示先选 project。
  • Readyproject 已选且 prompt 非空，主按钮进入可提交状态。
  • Creating按钮 loading，防止重复提交，同时保留文本内容。
  • Created显示 task/run 摘要，并把下一步动作指向 run detail。

Resolved later

这些配置不会进入首屏

它们仍然存在，只是被正确地推迟到服务端解析与 run detail 查看阶段。

  • workflow由 project default workflow 解析，不在这里下拉选择。
  • agent来自 workflow agent config，不让用户在首屏做多余判断。
  • repo / base branch取自 project lane 事实，不拆成单独配置表单。
  • runtime / runner由 control plane 解析 eligible capability，不做预检面板。
